## Guía para IA

1. **Tokens.** Nunca `bg-white`, `text-slate-*`, `bg-slate-*`, `border-slate-*`, ni paletas genéricas (`emerald-*`, `amber-*`, `blue-*`) para estados. Usar `bg-card`, `text-foreground`, `text-muted-foreground`, `bg-muted`, `border-border`, `primary` / `accent` / `accent2`, o constantes de `@/lib/ui-classes` (`CALLOUT_WARNING_CLASS`, `TEXT_SUCCESS_CLASS`, `TEXT_WARNING_CLASS`, `IMPORT_STAT_BADGE_CLASSES`, `TABLE_ROW_*`). Chrome de app (slidenav, `.section-header`, pies `.pie-pagina` / `tfoot` / `.finanzas-resumen-tarjeta` / footer de modal): `--sidebar` (azul oscuro).
2. **`cn()`.** Siempre. Prohibido `` className={`${a} ${b}`} ``. Una sola utilidad por eje (`px-8`, no `px-4 px-6 px-8`).
3. **Desktop-only.** Sin breakpoints Tailwind (`sm:`, `md:`, `lg:`, `xl:`, `2xl:`, `max-*:`). Las keys CVA `sm`/`md`/`lg` de `Button`/`AppModal` no son breakpoints. **Excepción única:** Envios · **Conductor** (lienzo fijo `w-[24rem]`, sin media queries).
4. **Cascarón.** Páginas a pantalla completa: `.area-page-shell` (opcional `bg-gris`). No duplicar `flex h-screen min-h-0 flex-col overflow-hidden`.
5. **Página con tabla.** `ClassicFilteredTableLayout` → `filters` = `FilterBar` `filtros-contenedor-tienda bg-card` → `children` = `.contenedor-tabla-gestion` + `Table` de `@/components/ui/table`. Padding horizontal lo pone el layout (`density` default `px-8`, `compact` `px-6`); vertical = `--espacio-filtros-vertical` (`.contenedor-pagina-con-filtros`). No repetir `px-*` ni `py-*` extra en filtros/tabla/children.
6. **Búsqueda.** `useFiltrosConBusqueda` + `FiltroBusquedaInput`. No reimplementar debounce ni foco. `matchByMultiTerm` (default: dígitos = token entero). Lista Clientes: `{ numericAsContains: true }` (CEL/CUIT por substring).
7. **Contorno de campos.** Todos los `Input`, `SelectTrigger`, `textarea`, combobox de valor y filas TRUE/FALSE (`ModalSiNoChoice` / `MODAL_BOOLEAN_SWITCH_ROW_CLASS`) llevan **línea 1px `--primary`** (`border-input`; token `--input` = `--primary`). No `border-border` ni `--gris-inset` en el recuadro del campo. Filtros: `.input-filtro-unificado` (mismo color + altura/tipo de filtro). Buscador del desplegable: `.select-search-input`. Superficie de lectura clicable (no CTA): `.boton-encubierto` (fondo transparente + mismo contorno; contenido centrado). Excepción: input **interno** de máscara/stepper (`border-0`) cuyo cascarón ya tiene el borde; igual el Select de catálogo de producto con **«+»** GESTIONAR (`ProductoTiendaCampos`: cascarón `border-input`, trigger `border-0`). Switch unchecked: `bg-gris-inset` (no `bg-input`).
8. **Selects / listas desplegables.** Prohibido `<select>` nativo y `<select multiple>`. Elegir **una**: `Select` shadcn (`SelectContent` con buscador **BUSCAR...**). Elegir **una o más**: `FiltroMultiSelect` (trigger `SELECT_TRIGGER_FILTER_CLASS` + panel portal `z-[90]` `role="listbox"` + `SelectSearchInput`; los checkboxes van **dentro** del panel; tildar no cierra el panel). No lista siempre visible de opciones (`<ul>` de recuadros con `<input type="checkbox">`). Valor vacío del Select: sentinel `"none"` / `"todos"` (Radix no admite `""`). Triggers de filtro: `SELECT_TRIGGER_FILTER_CLASS` + `className="select-content-filtro"` `position="popper" side="bottom" align="start"`. **Excepción:** botones cuadrados `Button` (`default`/`outline` + `border-primary`): `FacturaGenerarComprobanteModal` · **FORMA DE PAGO** (ícono `iconoFormaPagoDesdeNombre`; ENTIDAD / CUOTAS siguen Select), `FacturaDescuentoModal` toggle **DESC. POR FORMA PAGO** / **PERSONALIZADO** (`role="radiogroup"`, primero en el modal) y botones cuadrados de **FORMA DE PAGO** debajo (solo en DESC. POR FORMA PAGO) (`iconoFormaPagoDesdeNombre`; 2.º nivel **CUOTAS** más chicas `00` / `DEBITO`; filtran DESCUENTOS; grilla 90/10 con **Aplicar** a la derecha: aplica el desc. y cierra; pie **Cancelar** (PERSONALIZADO también **Aplicar**; sin **Aceptar**); `AppModal` `xl` `h-[85vh]` `scrollBody={false}` — altura fija; tabla `flex-1 overflow-auto` (vacío si hay pocas filas, scroll si hay muchas)); las reglas van en `Table` (no columnas), y **Generar Pedido** (`GenerarPedidoToolbarButton`: PROVEEDORES una opción; TIPO DE PEDIDO una o más).
9. **Tablas.** Un solo look: `.tabla-gestion-compacta`. Encabezados **MAYÚSCULAS + negrita**. Celdas `.celda-datos`. Vacío = `""` (no `"-"`/`"—"`; `fmtCelda` / `fmtNumero` de `@/lib/format`). Cantidad o stock: `fmtCantidad` (entero si no hay fracción; si no, un decimal `0,5`). No usar `fmtNumero` ahí (redondea y oculta 0,5). Scroll **solo** en `.contenedor-tabla-gestion` (el wrapper `data-slot="table-container"` **no** lleva `overflow-y-auto`). Sticky: `thead th`. 100 ítems/página (`PAGE_SIZE`). Botón solo ícono en fila: `variant="ghost"` `size="icon"` + `TABLE_ROW_ICON_BUTTON_FILLED_BRAND_CLASS` (no `outline` + `icon-xs`). Columna tilde: encabezado = ícono `Check`. **Control de ítem** (checklist local): `TablaControlItemHead` + `TablaControlItemCelda`; no duplicar el badge. Caja `.tabla-check-toggle`: rectángulo borde `#0072bb`, fondo `card`; tilde `#0072bb` si es verdadero (no rellenar con `bg-primary`).
10. **Modales.** `AppModal` (o `ModalTablaConFiltros` si hay tabla seleccionable). Botones: `Button` shadcn (`default` / `outline`). Configuración TRUE/FALSE o SÍ/NO: `ModalSiNoChoice` (etiqueta MAYÚSCULAS + `Switch`; **sin** texto de ayuda). No pares de botones SÍ/NO ni Select SI/NO si el valor ya es booleano. Excepción: tri-estado o “debe elegir” sin default (Select). Labels de campo: `text-foreground` (`ModalMicroLabel`). No `max-w-*` extra si coincide con `size`.
11. **Texto.** Títulos de modal: MAYÚSCULAS. Botones: Title Case. Sidebar: módulo MAYÚSCULAS, submódulo Title Case. **Alta de un elemento** (ítem de sidenav, botón de header o CTA): ícono `Plus` y etiqueta **Nuevo** / **Nueva** + el sustantivo, según el género (`+ Nuevo …`: **Nuevo Item**, **Nueva Venta**). No usar **Crear** ni **Agregar** como etiqueta. Filtros, placeholders y `TableHead`: MAYÚSCULAS. La máscara (campo vacío) se fuerza en `globals.css` con `text-transform: uppercase` en `input`/`textarea` `::placeholder`, en `[data-slot="select-trigger"][data-placeholder]` y en `button[data-placeholder]` (multi-select vacío). El valor elegido no se transforma. Abreviaturas con punto (Px., Cx., Dto., Cant., Cod.).
12. **Fechas de negocio.** `@/lib/fechaArgentina`. `@db.Date` → `isoYmdFromPrismaDateOnly` (no `dateToIsoYmdArgentina` sobre ese `Date`).
13. **Navegación interna.** `useRouter().push`, no `window.location.href`.
14. **Excepción hex (no copiar).** Solo **Balance mensual**: cabecera `#0072BB` + texto blanco; filas resultado `#a9d6f1` / `#063652`.
15. **Al cerrar.** Checklist **§4**. Clase global nueva → registrarla en **§2**.

## 1. Patrones

### 1.1 Página

```tsx
<div className="area-page-shell">
  <ClassicFilteredTableLayout
    title="Módulo"
    subtitle="Submódulo"
    actions={<>…</>}
    filters={<FilterBar className="filtros-contenedor-tienda bg-card">…</FilterBar>}
  >
    <div className="contenedor-tabla-gestion">
      <Table variant="compact">{/* … */}</Table>
    </div>
  </ClassicFilteredTableLayout>
</div>
```

- Header: `ClassicFilteredTableLayout` usa `ClassicPageHeader`. API ES: `SectionHeader`. Núcleo: `PageSectionHeader`. Fondo `--sidebar`; título/subtítulo `--sidebar-foreground`. Visual: **MÓDULO** → **SUBMÓDULO 1** → **Submódulo 2**. Fila del header en 3 columnas: módulo (izquierda) | **NOTIFICACIONES** (centro) | **ACCIONES** (derecha).
- **`actions` del header:** `PageSectionHeader` las envuelve en `HeaderAccionesMenu`. En pantalla hay **un** botón **ACCIONES** alineado a la **derecha**; al hover (o foco) se despliega la lista de la ventana. No dejar una fila de botones sueltos en el header. Los call sites siguen pasando `Button` / `ToolbarActionButton` / triggers de modal como `actions`. Escape cierra el menú.
- **NOTIFICACIONES del header:** `PageSectionHeader` renderiza `NotificacionesHeaderButton` **centrado** (ícono `Bell`, `Badge` `destructive` con no leídas, tope `99+`) solo si hay no leídas (`noLeidas > 0`). Sin ninguna notificación sin leer, el botón no se renderiza. Con no leídas: mismo `--primary` que **ACCIONES**. Destinatario = sucursal del usuario de pestaña (`leerUsuarioSesion`); sin usuario o con 401/403 no se muestra. Refresco: polling **60 s** (omite pestaña oculta) + cambio de ruta + `visibilitychange` + evento `EVENTO_NOTIFICACIONES_REFRESCAR` (`pedirRefrescoNotificaciones()` tras crear / resolver). Clic → `NotificacionesModal` (`AppModal` `xl` `h-[90vh]` `max-w-[min(96rem,calc(100%-2rem))]`; tabla **MÓDULO** | **DESCRIPCIÓN** | **ACCEDER**; módulo = `moduloEtiqueta` p. ej. **TRANS. DEPÓSITOS**; descripción = `mensaje` completo con salto de línea (`.celda-datos--crece`) + fecha; **Acceder** abre `StockTransferenciaModal` tras **450 ms**, no apilar `Dialog`; informativas se marcan leídas al acceder). No agregar otro botón de notificaciones por pantalla.
- `contentWidth`: `default` (`max-w-7xl`) | `wide150` (Comp. Categorías) | `full` (Balance, Gastos, Flujo, Calcular Lts, Px Tintométricos, Envios).
- El hueco encabezado → primer bloque lo pone `.contenedor-pagina-con-filtros` (`--espacio-filtros-vertical` = `1rem`). No añadir `py-4` en `children`.
- Card envolviendo tabla: `className={cn("card-tabla-envoltorio", "flex-1")}`.
- CFTL **sin** `filters`: Calcular Lts, Px Tintométricos (card de cálculo; acciones de editor en `actions`). Hubs vacíos: `return null`. Finder sin `FilterBar`: Catálogo Gastos, Comp. Categorías, Ideas Marketing. Envios · Programados abre el wizard de alta desde el header (sin finder de página).

### 1.2 Filtros

- `FilterBar` > `FilaFiltrosDesplegables` (default **5** columnas; `columnas={6}` solo con 6 Selects) + `FilterRowSearch` + `LimpiarFiltrosButton` (siempre visible).
- Si la pantalla usa **dos** `FilterBar` apilados, envolver ambos en `.filtros-doble-bloque-compacto` para compactar separaciones verticales y ganar filas visibles de tabla sin perder separación visual.
- Cada Select de página en `FiltroIndividualContainer`. En modal: `FiltroIndividualContainer` o `FiltroBusquedaInput` (X propia); no `LimpiarFiltrosButton`.
- Al limpiar un Select de filtros, el trigger debe volver a mostrar su placeholder (máscara). La máscara se ve siempre en MAYÚSCULAS (`text-transform: uppercase` en `globals.css`). A nivel app, `Select` normaliza `value null/undefined` a `""` para evitar que quede renderizado el último valor elegido.
- Consistencia recomendada en call sites: preferir `value={estado ?? ""}` (en vez de `|| undefined` / `?? undefined`) cuando el estado representa “sin filtro”.
- Sin búsqueda: **una sola fila**. El tacho (`LimpiarFiltrosButton`) va en `FILTER_INLINE_ACTION_SLOT_CLASS` (a menudo `col-span-2` si hay ≤3 Selects). Con **5 Selects**, el slot va a la derecha del grid (`FilterRowSelection` `flex-nowrap` + `shrink-0`); **no** una segunda fila. No mostrar contador de resultados (`X MOVIMIENTOS`, `X PRODUCTOS`, etc.).
- Rango de fechas: `FilterRowDateRange` + `FiltroRangoFechasCalendarioModal`.
- Multi-select (página o modal): `FiltroMultiSelect` (trigger `<button>` `SELECT_TRIGGER_FILTER_CLASS` + panel portal `fixed z-[90]` `role="listbox"` + `SelectSearchInput`; `disabled?`). Vacío = placeholder. El mismo patrón a mano solo si ya existe (`MktMultiSelectCatalogo`, tipo de pedido, meses/años). No `<select multiple>`. No `<ul>` de checkboxes a la vista.
- Sucursal vacía en Vendedor (pedidos / stock): `useAplicarSucursalPreferidaSiVacia`. Opciones de sucursal de pedido: `sucursales` con `pedido = true`. **Excepción:** Pedir Mercadería y Control Stock / Movimientos = sucursal del usuario de pestaña (`leerUsuarioSesion`); **sin** Select SUCURSAL.

### 1.3 Tablas

- Altura fila datos: `--tabla-body-row-min-height` (**2rem**). Encabezado: `--tabla-thead-height` (mín. 2 líneas).
- Bloque secundario: `tabla-bloque-secundario-head*` / `*-cell*` (`*-divider` = inicio de sub-bloque).
- Subencabezado en `tbody`: `TablaSubencabezadoSeccionRow`.
- **Control de ítem:** primera columna de checklist local (`TablaControlItemHead` + `TablaControlItemCelda`). Encabezado = ícono `Check` (`sr-only` LISTA DE VERIFICACIÓN). Celda: badge circular `bg-primary/20` si está marcado; hueco `h-7` si no. Las acciones (OK, etc.) van en **ACCIONES**. **Excepción Generar Nota Crédito DUX:** **OK** va a la izquierda del código en **COD. TIENDA** (sin columna ACCIONES); copiar cantidad a la derecha de CANT. Fila: `recepcion-fila-verificada` / `recepcion-fila-pendiente` (`.tabla-recepcion-pedido`). Usos: Recepción de Compra, Nota de Crédito (Compras).
- Pie de totales: o `TableFooter` en la misma tabla, o `.finanzas-resumen-tarjeta` bajo scroll (`contenedor-tabla-gestion--pie-fijo`). No segunda `<table>` de pie.
- Paginación URL: `PaginacionTabla`. Cliente: `PaginacionClient`. Backend: `skip`/`take` + `total` / `totalPaginas`.
- `<table>` nativo: solo `TablaGastos`, `PrintStock` (impresión) y leyenda de `GraficoMcVsPorcUtilidad`.
- Anchos estáticos: `<col className="w-[20%]" />`. `style` solo si el ancho es dinámico.

### 1.4 Modales

| Caso | Componente |
|------|------------|
| Formulario / confirmación | `AppModal` dentro de `Dialog` |
| Tabla + filtros + selección | `ModalTablaConFiltros` (`single` / `singleConfirm` / `multi` / `multiQuantity`) |
| Tabla de selección “vieja” ya migrada | Preferir `ModalTablaConFiltros` o `AppModal`; `modal-app` BEM sigue en call sites existentes (`SeleccionarProductoModal`) |

`AppModal`: `size` `sm|md|lg|xl` (md = `max-w-lg`), `padding`, `scrollBody` (default true), `hideBodyScrollbars`, `bodyShellClassName`. Tabla + pie fijo: tabla `flex-1 min-h-0`; no `h-0`. Wizard Envios · Nuevo Envío y Factura Crear · DESCUENTO (`FacturaDescuentoModal`): `size="xl"` `h-[85vh]` (`scrollBody={false}`; tabla `flex-1 overflow-auto`). No apilar dos `Dialog` a la vez. **Stacking:** overlay/contenido `z-[80]` (por encima del typeahead `z-[70]`); `SelectContent` y panel de `FiltroMultiSelect` en modal `z-[90]` (portal). **Boolean / SÍ/NO:** `ModalSiNoChoice` (`label` MAYÚSCULAS + `Switch` a la derecha; fila `MODAL_BOOLEAN_SWITCH_*`; **sin** texto de ayuda bajo la etiqueta). No botones SÍ/NO ni Select SI/NO para un booleano conocido. **Formulario seccionado** (modelo: `CrearEditarClienteModal`): `<section className="modal-seccion-formulario">` con encabezado `text-center text-xs font-bold uppercase tracking-wide text-foreground`; cada sección tiene contorno `1px` `--primary` y línea inferior `2px` `--primary` (no `border-t border-border`). **`FacturaGenerarComprobanteModal`:** un `Dialog` en dos pasos (no apilar). 1) **COBRO** (venta): formas de pago; **Agregar** con saldo 0 pasa solo a 2; **Continuar Con Saldo Impago** si queda saldo. Resumen cobros (entre **Agregar** y **Continuar Con Saldo Impago**): bloque `mx-auto max-w-md`; filas forma de pago + monto (`text-center`) + tacho; línea `border-primary/40` entre cobros, `border-b-2 border-primary` tras el último, luego **SALDO PENDIENTE**. 2) **GENERAR COMPROBANTE** (pie **Volver**; botones **GENERAR** / imprimir / descargar: `outline` + `border-primary` como formas de pago; al hover relleno `primary`, sin estado seleccionado). Cards `rounded-lg border border-border bg-muted/20 p-4`. Tri-estado o alta sin default (p. ej. Proveedor Mercadería, ¿discrimina IVA?) sigue en Select. **Catálogos «GESTIONAR…»** (modelo: Entidades): `AppModal` `size="lg"` título MAYÚSCULAS; buscador + `+` (`size="icon"` `h-10 w-10`); lista `border-border bg-card` con lápiz/tacho `TABLE_ROW_ICON_BUTTON_FILLED_BRAND_CLASS` `h-9`; alta/edición/baja en `Dialog` hijo `size="sm"`; el padre **permanece abierto** tras CRUD (solo Cerrar / X). No usar `key` en el page client que remonte al `router.refresh()` del catálogo. Si hay `Dialog` hijo, ignorar el `onOpenChange(false)` del padre al cerrar el hijo. **Formas Pago** (`GestionarPagosFinAnaCosFinaModal`): mismo cascarón; **sin** arrastre. Alta/edición: **NOMBRE** → **ENTIDADES** (`FiltroMultiSelect`; opcional, puede quedar vacío). No alta inline ni edición en la fila. **Cuotas** (`GestionarCuotasFinAnaCosFinaModal`): mismo cascarón. Alta/edición **CUOTAS** (texto único) y pares **FORMA DE PAGO** + **ENTIDAD** (botón +; solo el N:M de esa forma).. La lista de entidades se filtra al elegir la forma y no muestra las de otras formas. **Tipo Caja** (`GestionarTesoreriaTipoCajaModal`): mismo cascarón; alta/edición en `Dialog` hijo (código enum + nombre). No alta inline ni edición en la fila.

### 1.5 Finder

`@/components/shared/catalogo-finder/` + `CATALOGO_FINDER_*` en `ui-classes`. Columnas con header `bg-primary` (`headerVariant="finder"` default), `+` (`nuevoLado`: `end` default, `start` en Ideas), `className?` para altura en modal. Wizard Envios: `headerVariant="titulo"` (título de paso, sin barra primary) **en todos los pasos** (SUCURSAL / CLIENTES / DIRECCIONES / FECHA / MERCADERÍA). Paso CLIENTE / DIRECCIÓN: `mostrarNuevo={false}` y CTA **Nuevo Cliente** / **Nueva Dirección** (`Button` `w-full` en wrapper `p-4`, no `rounded-none`) debajo de la lista. Filas: hover editar/eliminar por default; `eliminarSiempreVisible` deja el `Trash2` fijo a la derecha (`CATALOGO_FINDER_COLUMN_NOVO_BUTTON_CLASS`). En Envios · CLIENTE y DIRECCIÓN, `accionesSiempreVisibles`: lápiz + Trash2 siempre visibles (DIRECCIÓN también MapPin). Selección `CATALOGO_FINDER_ROW_SELECTED_CLASS`. `nombreAccion` opcional a la derecha del nombre (Envios · DIRECCIÓN: `MapPin`). `iconoIzquierda` opcional a la izquierda del nombre (Envios · PINTOR: `Users`, filtra asociados). Envios · CLIENTE: `reservarEspacioIconoIzquierda` reserva el hueco `size-7` en CONSUMIDOR_FINAL para alinear nombres. `etiquetaIzquierda` opcional: columna fija de etiqueta a la izquierda. `nombreSufijo` opcional: ` - texto` en `font-normal text-[0.75em]` (Envios · CONSUMIDOR_FINAL con pintor asociado). Envios · DIRECCIÓN: `nombreContenido` + `EnviosProyectoListadoLineas` (3 líneas: nombre **negrita** / dirección / `(referencia)`). `nombre` = `etiquetaNombreProyecto` (aria). `nombreCentrado` centra el nombre (Envios · CLIENTE). Usos: Catálogo Gastos (5 cols), Comp. Categorías (4), Ideas (2), Envios · Crear Envío (finder 1 col por paso, dentro del wizard modal).

### 1.6 Sidebar y áreas

SSOT: `src/lib/appRoutes.ts` (URLs), `src/lib/main-app-areas.ts`, `administracionNav.ts`, `Sidebar.tsx`.

### 1.8 Typeahead / combobox listbox

Patrón de lista de sugerencias bajo un input (`role="combobox"` + panel `role="listbox"`). Usado en Factura · Crear (productos y clientes).

- **Debounce:** `useFiltrosConBusqueda` (≥ 3 caracteres tipico).
- **Typeahead de clientes reutilizable:** `FacturaClienteTypeahead` (`src/components/facturacion/`; props `seleccionado` / `onSeleccionar` / `id` / `placeholder`): solo elige cliente, sin alta ni edición. Usar en filtros nuevos en lugar de copiar el typeahead de Crear o Cuenta Corriente.
- **Texto fijado por código:** si el input **no tiene foco**, el hook repone `qActual`, así que un `setQ(...)` suelto se pierde. Cuando el valor se carga desde el código (cliente de `?cliente=`, clic en otra tabla, visor público), pasá ese mismo valor en `qActual` (estado propio, p. ej. `fijarTextoCliente` en Cuenta Corriente) y vacialo cuando el usuario escribe.
- **Panel:** `TYPEAHEAD_LISTBOX_PANEL_CLASS` (`z-[70]`). Altura fija por defecto: `TYPEAHEAD_LISTBOX_PANEL_HEIGHT_CLASS` (`h-72`). **Estirar al bloque padre** (Factura · Crear productos): overlay `absolute inset-4` del contenedor `p-4` + `TYPEAHEAD_LISTBOX_PANEL_FILL_BLOCK_CLASS` (desde debajo del input hasta el margen inferior interior; tapa tabla y pie). Ancla: `TYPEAHEAD_LISTBOX_ANCHOR_CLASS` / abierto `TYPEAHEAD_LISTBOX_ANCHOR_OPEN_CLASS` (`z-[60]`) para quedar por encima de bloques vecinos. Ancho = input → `TYPEAHEAD_LISTBOX_PANEL_MATCH_INPUT_WIDTH_CLASS`; más ancho → `TYPEAHEAD_LISTBOX_PANEL_WIDER_THAN_INPUT_CLASS`.
- **Lista:** `ul` con `TYPEAHEAD_LISTBOX_UL_CLASS` (scroll, sin línea entre ítems). Cebra y hover en `.typeahead-listbox-filas`: impar `--card`, par `primary` al 8 % sobre `--card`, hover y fila activa `primary` al 20 % (igual que `.tabla-gestion-compacta`). Cuerpo con columnas: `TYPEAHEAD_LISTBOX_BODY_SCROLL_CLASS` (`bg-popover` sólido; no transparente).
- **Encabezado de columnas (opcional):** `TYPEAHEAD_LISTBOX_HEADER_CLASS` (altura `--tabla-thead-height`, `bg-primary` + `text-primary-foreground` + `text-xs font-bold` como thead de tabla) + grid propio del módulo. Celdas `TYPEAHEAD_LISTBOX_CELL_CLASS` (`w-full text-center` + ellipsis). Con columnas: header **sticky** dentro de `TYPEAHEAD_LISTBOX_BODY_SCROLL_CLASS` (mismo ancho que las filas; el scrollbar no desfasá). En productos, grilla fija `FILA_BUSQUEDA_PRODUCTOS_GRID`: **COD.** | **DESCRIPCIÓN** | **PX. LISTA** | **PX C/ DESC.** | **STOCK** | **DESC. ESPECIAL** (`$` + `fmtPrecio`; **PX C/ DESC.** usa el % de forma de pago / personalizado, igual a lista si no hay desc.). Promo `desc_promo` alcance **ITEMS**: ícono `Percent` (mismo de **Desc.**; `TABLE_ROW_ICON_BUTTON_FILLED_BRAND_CLASS`, `stopPropagation`) solo en esa fila; abre `FacturaDescEspecialesItemModal` (`lg`, título **DESC. ESPECIAL**; tabla **NOMBRE** | **DESC.** | **FORMA DE PAGO** | **PRIORIDAD**). Sin especial, la celda queda `""`. **STOCK**: solo la cantidad de la sucursal activa (`fmtCantidad`, también 0); el número es botón (`TYPEAHEAD_STOCK_CANT_BTN_CLASS`) y abre `FacturaProductoStockModal`: título **STOCK POR SUCURSALES**; en el cuerpo, **SOLICITADO** (nombre del ítem) y **STOCK** (sucursal activa en `border-primary` `bg-primary/10` y tabla del resto, sin títulos de grupo). Desde el remito suma **MOVIMIENTOS** si la sucursal activa no cubre la cantidad. En clientes: mismo cascarón (header sticky + `ul` `flex-none overflow-visible`); grid `CLIENTE` / `PINTOR` / `SALDO`. Orden de filas: coincidencia en **CLIENTE** primero (el pintor si se busca su nombre), después asociados A-Z.
- **Fila:** `li role="option"` → **`div role="button" tabIndex={-1}`** con `TYPEAHEAD_LISTBOX_OPTION_ROW_CLASS` + activo `TYPEAHEAD_LISTBOX_OPTION_ACTIVE_CLASS` (marca; el fondo lo resuelve `.typeahead-listbox-filas` vía `aria-selected` / esa clase). En **clientes** (Crear y Cuenta Corrientes) sumar `TYPEAHEAD_LISTBOX_OPTION_ROW_CLIENTES_CLASS` (`min-h-7 py-1.5`) para más aire entre ítems; productos typeahead `min-h-7 py-1` (no `py-0`). **No** usar `<Button>` ni `<button>` para la fila completa (sí un `Button` anidado si hace falta, p. ej. stock o ícono **DESC. ESPECIAL**).
- **Cierre:** click fuera del wrap; Escape; al elegir.
- **Búsqueda avanzada (Factura · Crear):** **Desc.** (`Aplicar descuento`) a la izquierda del bloque lupa + input; siempre habilitado, aunque el remito esté vacío. Lupa `Button` `variant="default"` `size="icon"` junto al input de productos. Abre `FacturaBusquedaAvanzadaModal` (`AppModal` `size="xl"` `h-[85vh]`). Fila 1: RUBRO, SUBRUBRO, MARCA (`Select` dentro de `FiltroIndividualContainer`: tacho si hay valor; sentinel `todos`). Fila 2: DESCRIPCIÓN (`useFiltrosConBusqueda` + `FiltroBusquedaInput`; mín. 3 letras si es el único filtro). La lista es `FacturaProductoBusquedaLista` (mismo encabezado y cebra que el typeahead). Filas del modal: `min-h-10` (2.5rem); el typeahead en `main` usa `min-h-7 py-1`. Clic en la fila agrega el ítem al remito, cierra el modal y enfoca `CANT.` de la línea recién creada. `CANT.` admite un decimal (`0,5`); el default y la pantalla son enteros si no hay fracción (`fmtCantidad`). El número de **STOCK** cierra este modal y abre el de sucursales (no se apilan); al cerrarlo vuelve la búsqueda. El ícono **DESC. ESPECIAL** igual (`FacturaDescEspecialesItemModal`; no se apila).
- **Stacking:** si el listbox queda bajo otra zona (p. ej. remito Factura `z-30`), subir el **card de cabecera** al abrir (`TYPEAHEAD_LISTBOX_ANCHOR_OPEN_CLASS` = `relative z-[60]`). En Factura · Crear · CLIENTE el panel flota sobre el bloque de líneas; sin subir la card se ve el remito encima y la lista parece transparente.

Constantes: `@/lib/ui-classes` (`TYPEAHEAD_LISTBOX_*`).

## 5. Anti-patrones

- Paletas genéricas, breakpoints responsive, `<select>` nativo, `<select multiple>`, lista siempre visible de checkboxes para elegir una o más opciones de catálogo, `window.location.href`, template literals en `className`, cascarón `h-screen flex…`, sombra mágica en Card de tabla.
- Recuadro gris (`border-border` / `--gris-inset`) en `Input`, `SelectTrigger`, `textarea`, combobox o `ModalSiNoChoice`. El contorno de campo es `--primary`.
- `<button>` suelto en páginas/modales (usar `Button`). Excepciones: celdas de calendario, checkbox de tabla, `TooltipTrigger`, barras de gráfico, dock/sidebar, trigger de multi-select, `.boton-encubierto` (lectura clicable; el CVA de `Button` rompe truncado / `text-left`).
- `Button` que abre un selector disfrazado de campo (`justify-start` + texto `text-foreground`): si es una acción, va como botón principal (`variant="default"`, texto centrado en Title Case). En Nuevo Item: **VINCULAR PROD. PROVEEDOR** y **Agregar Componente**, sin micro-label.
- Botones o consultas de sync con DUX (eliminado; la app no consulta la API DUX).
- Inventar layout “dashboard” o segunda variante de tabla.
- Fila de botones sueltos en el header de página (usar `actions` → menú **ACCIONES**).
- Etiqueta **Crear** o **Agregar** para dar de alta un elemento (usar `Plus` + **Nuevo** / **Nueva** + sustantivo).
- Recrear páginas en URLs redirigidas (`/proveedores`, `/proveedores/gestion`, `/finanzas/flujo-de-fondo`, `/finanzas/deuda-proveedores`, `/finanzas/venc-proveedores-mercaderia`, `/precios-competencia`, …).
- Copiar el hex de Balance mensual a otras pantallas.
- Lógica de negocio, auth o persistencia en el cliente.
- Array u objeto (prop con default `= []`, `.map(...)` inline) en las dependencias de un `useEffect` que hace `setState`: se crea nuevo en cada render y el efecto entra en bucle (traba la app). Derivar una clave primitiva (p. ej. `ids.join("|")`, como `SeleccionarProductoModal`) y no reasignar `[]` si ya está vacío.
