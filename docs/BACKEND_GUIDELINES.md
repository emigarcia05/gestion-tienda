## Guía para IA

1. **Action** = sesión (`getRol` / `esEditor`) + permiso (`puede` / `PERMISOS`) + Zod (`unknown` + `safeParse`) + delegación a `src/services/`. Devolver `ActionResult`.
2. **Autorización primero.** Antes de parsear o tocar servicios. No confiar en que el layout protege la página.
3. **Prohibido `any`.** TypeScript estricto.
4. **Sin lógica de negocio pesada ni Prisma en Actions nuevas.** Legacy documentado en **§5** (tienda/stock/reposición/vínculos/tipos pintura): no copiar el patrón.
5. **Una sola entrada por operación.** No Action + API route duplicados. Jobs largos (import, scraping) = Route Handler.
6. **Mutaciones críticas:** gate doble módulo + `esEditor()`, salvo excepciones de **§1.2.3**.
7. **IDs:** `cuid` → `prismaCuidSchema`; UUID → `uuidSchema`; mixto → `prismaCuidOrUuidSchema` / `globalSucursalIdSchema`; `cod_ext` / `cod_tienda` → esquemas en `@/lib/validations/common`.
8. **Errores:** `{ ok: false, error: string }` controlado. No stack ni SQL al cliente. Loguear en servidor con prefijo `[modulo][fn]`.
9. **TZ:** `@/lib/fechaArgentina`. No `Date#getHours()` ni `toLocaleDateString` sin `timeZone`.
10. **Naming:** Px Competencia = `pxCompetencia*`. Px Listas DUX = `pxListasPrecios*`. Ver **§5**.
11. **Gates repetidos:** `@/lib/actionGates.ts` (finanzas / marketing / facturación / estadísticas / Asistente IA / gasto eventual). API: `@/lib/apiRouteAuth.ts`.
12. **Errores Zod / ServiceResult en Actions:** `@/lib/actionResult.ts` (`firstZodErrorMessage` lee `issues[0].message`, `zodFail`, `fromServiceResult`). No copiar flatten local (`flatten()` en Zod 4 no tipa `string`).
13. **Al cerrar:** actualizar este documento (modelo, servicio, regla o patrón). Lint: `npx eslint src --max-warnings 0`.
14. **Cantidad / stock:** `vtas_comprobantes_items.cantidad` y `stock_movimientos.cantidad` son `Decimal(12,1)` (hasta un decimal). Zod `cantidadUnDecimalPositivaSchema` (`@/lib/cantidadUnDecimal`). No `Int` ni más de un decimal.

## 1. Principios

### 1.1 Server Actions (`src/actions/`)

- `"use server"` al inicio. Exports: **`export async function`**. **No** re-exportar valores de runtime (strings, Zod, constantes); dispara `invalid-use-server-value`. `export type` sí. Literales compartidos: `src/services/` o `src/lib/`.
- Rol: orquestadores I/O. Firma `async`, tipado estricto.
- **Anti-patrón:** una Action no llama a otra Action. Extraer al servicio.

### 1.2 Seguridad

#### 1.2.1 Sesión (`src/lib/sesion.ts`)

- **iron-session** vía `getSesion()`, `getRol()`, `getIdPersonalSesion()`, `esEditor()`. `SesionData = { rol, idPersonal? }` (cookie `gestion-rol`, 8 h).
- **Ingreso por usuario** (`/ingresar`, sin clave por área): sucursal → usuario → contraseña. Actions en `src/actions/sesion.ts` (lógica en `src/services/ingreso.service.ts`, Zod en `src/lib/validations/ingreso.ts`, min 4 / max 128): `listarUsuariosIngresoAction` (pública; solo usuarios con sucursal **y** ≥1 módulo; devuelve `tieneContrasena`, nunca el hash), `ingresarUsuarioAction` (verifica hash), `crearContrasenaUsuarioAction` (solo si `contrasena IS NULL`, `updateMany` condicional; pide confirmación), `cerrarSesionAction` (`destroy`). Al ingresar se guarda `idPersonal` y **`rol = rolDesdeModulosPermitidos`** (`src/lib/ingreso.ts`): `editor` si `modulos_permitidos` incluye `finanzas` (Administrador), si no `simple`. Si cambian los módulos, el rol se recalcula en el próximo ingreso. `activarModoEditor` / `ADMINISTRADOR_PASSWORD` **eliminados**.
- **Middleware:** sin cookie de arranque `tienda-app-arranque` (sin `maxAge`; nueva sesión de navegador) borra la cookie iron-session; sin cookie iron-session redirige a `/ingresar` salvo rutas públicas (`/ingresar`, `/cc/*`, `/conductor/*`). **Visor Conductor:** `/conductor/{token}` fija la cookie httpOnly `tienda-conductor-visor` (`src/lib/enviosConductorPublico.ts`); con esa cookie cualquier otra ruta redirige al visor, salvo `/ingresar`, que borra la cookie (sigue pidiendo contraseña). Pasa el pathname en `x-tienda-pathname`. El layout raíz carga el usuario (`obtenerUsuarioSesion`, módulos frescos de BD) y redirige a `/ingresar` si no hay `idPersonal` válido. Rutas `/api/*` fuera del matcher (las Actions/API siguen protegidas por rol, no por usuario).
- Usuario de pestaña: copia en `sessionStorage` (`main-app-usuario-sesion`) que `AppShell` sincroniza desde la sesión del servidor (pestañas nuevas incluidas). Sucursal preferida se copia de `usuarios.sucursal_por_defecto`. Al emitir un comprobante se escribe `vtas_comprobantes.personal_id`. Envios · Conductor interno (`/ventas/envios/conductor`) también exige ingreso (sin slidenav); el chofer usa el link público `/conductor/{token}` (ver §3 Envios).
- `getRol()` ante cookie inválida: `"simple"` + log `[sesion][getRol]` (no tumbar el layout).

#### 1.2.2 Checklist por Action (obligatorio, en este orden)

1. **Autorización:** `getRol()` / helper de `@/lib/actionGates` / `esEditor()` + `puede(rol, PERMISOS.*)`.
2. **Payload `unknown`** desde el cliente + `.safeParse()`. Prohibido tipar la firma con `z.infer` (el cliente ignora TS). Excepción: `FormData` o un ID `string` suelto, igual con Zod interno.
3. **IDs** según modelo Prisma (**§1.2.4**).
4. **Delegar** al servicio; `revalidatePath` de rutas canónicas; devolver `ActionResult`.
5. **Sin fugas:** `try/catch` alrededor de Prisma/servicios que puedan lanzar. Lecturas con shape vacío ante error (no stack).

#### 1.2.3 Gate doble: módulo + editor

Convención: `puede(rol, PERMISOS.<modulo>…)` **antes** de `esEditor()`. El primero rechaza acceso conceptual; el segundo rechaza modo solo-lectura.

**Excepciones (simple y editor pueden mutar):**

Cada sucursal es depósito. Flujo vendedor. |

#### 1.2.5 Superficie mínima y ENV

- Action sin call sites → eliminarla (`node scripts/audit-actions-usage.mjs`).
- Toda lectura `process.env.*` listada en **`.env.example`**. Obligatorios en prod: `SESSION_SECRET`, `DATABASE_URL`.
- **Sin integraciones externas de datos (2026-10-27):** la app no consulta la API de DUX ni Google Sheets. Se eliminaron `@/lib/googleSheets.ts`, `googleSheetsWrite.ts`, `googleSheetsProbe.service.ts`, `googleSheetsExportMktSecciones.service.ts`, `actions/googleSheets.ts`, `ExportarMktSeccionesGoogleSheetsButton` y `npm run test:google-sheets`. Las variables `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY` y `GOOGLE_SHEETS_SPREADSHEET_ID` ya no se leen. No reintroducir.

### 1.3 Integridad y zona horaria

- Todo payload que toque BD: Zod **antes** de usarse. Preferir validar en la Action; en el servicio si se reutiliza.
- **`@/lib/fechaArgentina`**: `TIMEZONE_ARGENTINA = "America/Argentina/Buenos_Aires"`. PDFs, nombres de archivo, “hoy” de negocio. Días entre calendarios `YYYY-MM-DD`: `diffCalendarDaysIsoYmdArgentina`.
- Solo fecha calendario (`YYYY-MM-DD` sin hora, p. ej. factura DUX): parsear partes ISO (`parseIsoYmdParts`), no el TZ del runtime.

### 1.4 Arquitectura

- **Servicios** (`src/services/`): Prisma / SQL / reglas. Las Actions los invocan; no al revés.
- **Prisma / Neon:** `DATABASE_URL` = pooler (runtime `src/lib/prisma.ts`). Migraciones: `DIRECT_URL` (host sin `-pooler`) en `prisma.config.ts`. El pooler no sostiene `$transaction` interactiva: writes sueltos de stock van en un `create` anidado (`registrarStockMovimientos` sin `db`). **P3009** (migración fallida en `_prisma_migrations`): Prisma no aplica nada más hasta resolverla. No borrar carpetas de migraciones ya aplicadas. Si el SQL falló por un nombre de tabla intermedio, hacer la migración **idempotente**, `prisma migrate resolve --rolled-back <nombre>` y `prisma migrate deploy`. No editar migraciones que ya terminaron `finished_at`.
- **URLs:** árbol `/{área}/{módulo}/{función}` con SSOT `APP_ROUTES` (`src/lib/appRoutes.ts`; detalle en FRONTEND §1.7). Mutaciones: `revalidatePath` **solo** con constantes derivadas de `APP_ROUTES` (sin literales ni rutas legacy: las URLs viejas son redirects de `next.config.ts`, no páginas).
- **`stockeable`:** `prod_tienda_stock` **eliminada**. `whereProdTiendaStockeable` no filtra y `buildMapStockeable` / `isStockeableCodTienda` dan **false**. Cada sucursal es depósito; el saldo es Σ `stock_movimientos` (INGRESO +, EGRESO −). `DUX_ID_STOCK_*` solo para recepción DUX (`id_deposito` del POST `/v2/compras`).
- **Vínculo tienda ↔ proveedor:** 100 % manual. Única relación vigente: `proveedores_prod_lista.cod_tienda`. Sync DUX **no** escribe `proveedor` ni auto-vincula. `prod_lista.cod_ext` no existe.
- **`prod_lista.bulto`:** unidades por bulto (`Int?`). `null` = vacío. CHECK SQL `prod_lista_bulto_positivo` (`"bulto" IS NULL OR "bulto" > 0`). Sync DUX **no** escribe esta columna. Persistencia: `tiendaBultos.service.ts`. **No** reintroducir `prod_tienda_bultos` / `ProdTiendaBulto`.
- **Lotes DUX:** 50 ítems/lote (`DUX_API_BATCH_SIZE` / `DUX_API_PAGE_LIMIT`); pausa ≥ 5 s (`DUX_API_BATCH_INTERVAL_MS`). Timeout HTTP `DUX_FETCH_TIMEOUT_MS` (default 30 s) cubre fetch+JSON, no el backoff 429.

### 1.5 Errores y respuestas

```ts
// Actions — @/lib/types
type ActionResult<T = void> = { ok: true; data: T } | { ok: false; error: string };

// Servicios — @/types (service.types)
type ServiceResult<T = void> = { success: true; data: T } | { success: false; error: string };
```

No lanzar al cliente. `sesion.ts` puede devolver `{ ok, error? }`. Traducción `ServiceResult` → `ActionResult` y primer error Zod (`issues[0].message`): `@/lib/actionResult.ts`.

**Error boundaries RSC:** `src/app/global-error.tsx` + `error.tsx` por ruta que lea Prisma. `catch` en servicios con prefijo grepeable (`[pedidoHistoria]`, `[sesion][getRol]`, etc.).

## 2. Patrones de código

### 2.1 Action con gate + Zod + servicio

```ts
"use server";

import { revalidatePath } from "next/cache";
import { requireEditorFinanzas } from "@/lib/actionGates";
import { firstZodErrorMessage, fromServiceResult } from "@/lib/actionResult";
import type { ActionResult } from "@/lib/types";
import { crearAlgoSchema } from "@/lib/validations/algo";
import { crearAlgo } from "@/services/algo.service";

export async function crearAlgoAction(raw: unknown): Promise<ActionResult<{ id: string }>> {
  const gate = await requireEditorFinanzas();
  if (gate) return gate;

  const parsed = crearAlgoSchema.safeParse(raw);
  if (!parsed.success) {
    return { ok: false, error: firstZodErrorMessage(parsed.error) };
  }

  try {
    const out = fromServiceResult(await crearAlgo(parsed.data));
    if (!out.ok) return out;
    revalidatePath("/ruta-canonica");
    return out;
  } catch (e) {
    console.error("[crearAlgoAction]", e);
    return { ok: false, error: "No se pudo crear." };
  }
}
```

`FormData` (alta proveedor, etc.): armar `raw` desde `formData.get(...)` y `safeParse` igual. El gate de módulo concreto (`PERMISOS.proveedores.acciones.nuevoProveedor`) va **antes** del parse. Helpers de error: `@/lib/actionResult.ts`.

### 2.2 Lectura sensible (permiso + Zod + shape vacío)

```ts
// Preferir RSC → servicio (sin Action) cuando el cliente no invoca la lectura.
export async function loadPxListasPage(params: unknown) {
  const rol = await getRol();
  if (!puede(rol, PERMISOS.cxPxTienda.acceso)) {
    return emptyPxListasPreciosPageData();
  }
  const parsed = getPxListasPreciosPageParamsSchema.safeParse(params);
  if (!parsed.success) return emptyPxListasPreciosPageData();

}
```

Listados pesados de página: preferir **RSC → servicio** (sin Action) cuando el cliente no invoca la lectura. **Px Listas** carga el listado desde el RSC (`getPxListasPreciosPageDataFromDb`); las Actions del módulo son solo mutaciones/export. El shape vacío de permiso/Zod **no** debe ejecutar Prisma (DISTINCT / count).

## 3. Dominios

### 3.1 Proveedores y usuarios

**`proveedores`** (`Proveedor`): `id` cuid. `id_proveedor_dux` único (varios `NULL` OK; valor no nulo único). FK referenciada por `fin_compras_comprobante.id_proveedor` (`onDelete: Restrict`).

| Campo | Regla |
|-------|--------|
| `proveedor_mercaderia` | Default alta `false`; UI mercadería default SI. Filtros de Ventas · COMPRAS y Administrador · PROVEEDORES → solo `true`. `getProveedoresMercaderia` / `getProveedoresNoMercaderia` / `getProveedores`. |
| `es_fabrica` | Opt-in. Pedido A Fáb. + retención historial 60/14 días. |
| `tiempo_entrega_en_dias` | Integer nullable 0–999. |
| `coeficiente_tintometrico` | `> 0`, hasta 6 decimales. Edición masiva: `actualizarCoeficientesTintometricosAction` (`stock.acceso` + editor). |
| `plazo_pago_1_dias` … `plazo_pago_4_dias` | Plan de pago (días). 1.º obligatorio en UI (default cálculo 30). 2–4 opcionales, crecientes. Valores `PLAZOS_PAGO_DIAS_PERMITIDOS` = 0, 30, 60, 90, 120, 150 (0 = vence el día del comprobante; vencido desde el día siguiente, regla `fecha_venc < hoy`). `fecha_venc = fecha_comp + dias` (piso 0, TS y SQL). Cuotas iguales sobre total; pagos FIFO. |
| `iva` | Enum `IvaProveedor`: `SIEMPRE` \| `NUNCA` \| `PREGUNTA` (default). Transversal (también `bal_gasto.iva`). Zod: `@/lib/validations/iva.ts`. |
| `prefijo` | Opcional; 3 letras A-Z o `null`. |

CRUD: `src/actions/proveedores.ts` + `proveedor.service.ts`. Mutaciones: `PERMISOS.proveedores.acciones.nuevoProveedor`. Lectura catálogo: al menos uno de `sugeridos` / `lista` / `importarLista`. Eliminar: servicio `deleteProveedor` (`ServiceResult`; respeta FK).

**`usuarios`** (ex `personal` / `global_personal`; Prisma `GlobalPersonal` `@@map("usuarios")`): PK `id_personal` (serial; el alta no lo pide). **`id_dux`:** vínculo DUX hacia otras tablas (TEXT, unique si informado; varios NULL OK). Filas existentes: `id_dux` = `id_personal`. Alta nueva: el usuario carga `id_dux` (opcional; no se copia el PK). `sucursal_por_defecto` (nullable) + `modulos_permitidos` (ids de `MainAppAreaId`: `gestion-productos` \| `finanzas` \| `marketing` \| `area-finanzas`; Zod; CHECK SQL `usuarios_modulos_permitidos_check`) + `titular_financiero` (boolean, default `false`) + **`super_usuario`** (boolean, default `false`, migración `20261008200000_usuarios_super_usuario`): modo **SUPER** = acceso a **todos** los módulos de `MAIN_APP_AREAS`, incluidos los que se agreguen después; `modulos_permitidos` se conserva pero se ignora. Resolver siempre con `modulosEfectivosUsuario(modulos, superUsuario)` (`src/lib/usuarios.ts`; lo usan `ingreso.service` y el listado de vendedores de comprobantes); como incluye Administrador, SUPER ingresa con rol `editor`. Zod: sin SUPER exige ≥1 módulo + **`contrasena`** (`TEXT NULL`, migración `20261008190000_usuarios_contrasena`): guarda **solo el hash** (scrypt de Node vía `src/lib/contrasena.ts`, formato `scrypt$N$r$p$salt$hash`, comparación `timingSafeEqual`), **nunca** texto plano; null = sin contraseña (el usuario la crea en su próximo ingreso). El cliente Prisma la **omite por defecto** (`omit: { globalPersonal: { contrasena: true } }` en `src/lib/prisma.ts`), así ningún `findMany`/`include`/`create` la expone; leerla solo en servidor con `select: { contrasena: true }` u `omit: { contrasena: false }` y **mapear a boolean** (`tieneContrasena`) antes de devolver (`ingreso.service.ts`, `globalPersonal.service.ts`). Ingreso: ver §1.2.1. Restablecer: `restablecerContrasenaUsuarioAction` (`usuarios.acceso` + editor; pone `contrasena = NULL`). Alta: `crearUsuarioPersonalAction` (`usuarios.acceso` + editor). Update: `actualizarUsuarioPersonalAction` (`usuarios.acceso` + editor). Baja: `eliminarUsuarioPersonalAction` (`usuarios.acceso` + editor); si el nombre figura como `tesoreria_cajas.titular`, se rechaza. Lista catálogo (Usuarios): `listGlobalPersonal` en RSC. Recepción DUX usa el `idPersonal` del usuario slidenav (`leerUsuarioSesion`); no hay modal **Elegir Personal**. Renames: `20260922180000_rename_global_personal_to_personal` + `20261005120000_personal_to_usuarios_stock_movimientos_usuario`. Las FKs de otras tablas siguen como `personal_id` → `usuarios.id_personal`.

### 3.2 Lista de precios proveedor
